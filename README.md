# PDF Outline Maker

Програма робить дві речі:

* **`export.bat`** — перетворює `.md` на PDF зі змістом. Верстку робить сам
  Obsidian, тож вигляд точно такий, як у його «Export to PDF», — але із
  закладками. Заголовки беруться з розмітки, тому зміст завжди точний.
* **`run.bat`** — додає зміст до вже готових PDF, у яких його немає
  (чужі файли: Beamer, Word, doPDF). Заголовки визначаються за виглядом тексту.

Перший спосіб точніший, другий — універсальніший.

## Нотатки Obsidian: `export.bat`

```
md\Лабораторна робота 5.md   ->   md\Лабораторна робота 5.pdf
```

1. Покладіть `.md` у теку `md`.
2. Двічі клацніть `export.bat`.
3. Дайте відповідь на три питання — формат аркуша (типово `A4`), чи робити
   назву файлу заголовком (типово так) і масштаб у відсотках (типово 100).
   Enter лишає значення за замовчуванням.
4. Заберіть PDF із тієї самої теки.

Потрібен **запущений Obsidian** — саме він малює сторінки. Плагін
`pdf-outline-export` програма ставить у сховище сама; після першого
встановлення (і після кожного оновлення файлів плагіна) Obsidian треба
перезавантажити — `Ctrl+R` у його вікні. Програма про це попереджає.

### Ключі командного рядка

```bat
export.bat --yes
export.bat --page-size A3 --downscale 80
export.bat "C:\Нотатки\Лаб 5.md" -o "D:\PDF"
export.bat --input "C:\Нотатки" --no-include-name
```

| Ключ | Призначення |
|---|---|
| `--page-size A3\|A4\|A5\|Legal\|Letter\|Tabloid` | формат аркуша (типово `A4`) |
| `--include-name`, `--no-include-name` | назва файлу першим заголовком (типово так) |
| `--downscale N` | масштаб 10..100 % (типово 100) |
| `--landscape`, `--no-landscape` | орієнтація аркуша |
| `--margin default\|minimal\|none` | поля сторінки |
| `--outline md\|chromium` | хто будує зміст (типово `md` — програма) |
| `--input`, `-i` | інша тека з `.md` (типово `md`) |
| `--output`, `-o` | складати PDF в окрему теку |
| `--vault` | сховище Obsidian (назва або шлях), якщо їх кілька |
| `--open` | відкрити готовий PDF у переглядачі |
| `--timeout СЕК` | скільки чекати на Obsidian (типово 180) |
| `-y`, `--yes` | нічого не питати |
| `--no-tree`, `-v`, `-q` | коротший / докладний / мовчазний вивід |

Постійні значення зручніше тримати у `config.json`, секція `export`
(зразок — у `config.example.json`).

### Чому вигляд точно такий, як в Obsidian

Програма нічого не перемальовує. Сторінки друкує сам Obsidian: плагін бере
те саме внутрішнє вікно експорту, що й пункт меню «Export to PDF», і
викликає його з тими самими налаштуваннями. Тема, шрифти, математика,
callouts, таблиці — усе як на екрані.

Зміст дописується окремо: заголовки беруться з `#`-розмітки вхідного `.md`
(рівні й назви там точні за визначенням), а сторінка й точка переходу —
пошуком цього тексту в готовому PDF.

Chromium уміє скласти зміст і сам (`--outline chromium`), але за це він
будує ще й повне дерево доступності — tagged PDF. На справжній лабораторній
(89 КБ, 60 формул) це понад **п'ять хвилин** замість п'яти секунд, а на
нотатці з математикою файл роздувається з 86 КБ до 1,4 МБ. Тому типово
зміст будує програма: ті самі 20 пунктів з'являються за 0,2 с.

У самому Obsidian з'являється й команда **«Export to PDF with outline»** —
експорт відкритої нотатки зі звичайним вікном вибору файлу (там зміст
будує Chromium, бо `.md` програма в цей момент не бачить).

### Дрібниці, про які варто знати

* Файл **зі сховища** друкується як є: працюють вкладення, вікілінки, теми.
* Файл **поза сховищем** плагін тимчасово копіює до теки
  `_pdf-outline-export-temp` у сховищі (разом із малюнками, на які нотатка
  посилається відносними шляхами) і видаляє її одразу після друку.
  Посилання `[[на інші нотатки]]` в такому файлі лишаться нерозкритими.
* **Перший друк після запуску Obsidian** виходить інакшим за всі наступні:
  математика доверстується вже по дорозі, і на двадцяти сторінках набігає
  зайва. Вада не наша — штатний експорт Obsidian поводиться так само. Якщо
  Obsidian запущено менш ніж дві хвилини тому, програма сама робить для
  першого файлу контрольний повтор і лишає другий результат.
* Нотатка без заголовків дасть PDF із порожнім змістом — програма про це скаже.
* Готовий файл перевіряється відразу: у консоль друкується дерево закладок.
  `-v` додатково показує, скільки часу забрав кожен етап.

### Якщо щось пішло не так

* **«Obsidian не відповів за 180 с»** — застосунок не запущений, або плагін
  ще не завантажений. Перезавантажте Obsidian (`Ctrl+R`) і перевірте, що
  `PDF outline export` увімкнено в Settings → Community plugins.
* **«немає доступу… файл відкритий у переглядачі»** — закрийте готовий PDF.
* **Зміст порожній** — у нотатці немає заголовків `#`, або вони всі всередині
  блоків коду.

## Готові PDF: `run.bat`

Програма бере PDF-файли з теки `data`, сама визначає в них заголовки
й зберігає копії з готовим змістом (document outline — панель закладок
у переглядачі PDF).

```
data\lab1.pdf                  ->  data\lab1_outline.pdf
data\Практичне заняття 2.pdf   ->  data\Практичне заняття 2_outline.pdf
```

Вміст сторінок не змінюється: текст, векторні формули, рисунки й посилання
лишаються точно такими, як були. У файл дописується лише дерево закладок.

## Як користуватися

1. Покладіть PDF у теку `data`.
2. Двічі клацніть `run.bat`.
3. Заберіть файли `*_outline.pdf` із тієї ж теки.

Перший запуск сам створить віртуальне середовище `.venv` і встановить
залежності — це займе хвилину. Наступні запуски миттєві.

Файли, чия назва вже закінчується на `_outline`, програма ніколи не обробляє,
тож повторний запуск не створює `lab1_outline_outline.pdf`.

## Що програма робить із файлом

| Ситуація | Поведінка |
|---|---|
| Звичайний PDF із заголовками | Будує зміст за виглядом тексту |
| PDF, у якому зміст уже є | Переносить наявний (див. `--existing`) |
| Поруч лежить `<ім'я>.outline.json` | Бере зміст із цього файлу |
| Скан без текстового шару | Повідомляє й нічого не створює |
| Пошкоджений або захищений паролем | Повідомляє про помилку і йде далі |

## Ключі командного рядка

Їх можна дописувати просто після `run.bat`:

```bat
run.bat --dry-run
run.bat --input "D:\Конспекти" --recursive
run.bat --max-depth 2 --no-tree
run.bat --existing regenerate
run.bat "C:\шлях\до\одного.pdf"
```

| Ключ | Призначення |
|---|---|
| `--dry-run`, `-n` | показати знайдені заголовки, нічого не записуючи |
| `--input`, `-i` | інша тека з вхідними файлами (типово `data`) |
| `--output`, `-o` | складати результати в окрему теку |
| `--recursive`, `-r` | шукати PDF і в підтеках |
| `--existing keep\|regenerate\|skip` | що робити з файлом, у якому зміст уже є |
| `--fallback none\|pages` | якщо заголовків немає: нічого або закладка на сторінку |
| `--max-depth N` | скільки рівнів лишити у змісті (типово 4); глибші пункти відкидаються, решта лишається на місці |
| `--expand-levels N` | до якого рівня розгортати панель закладок (типово всі) |
| `--title-node` | загорнути зміст у пункт з назвою документа |
| `--no-open-bookmarks` | не розгортати панель закладок при відкритті файлу |
| `--rewrite` | перезаписати PDF повністю замість дозапису в кінець |
| `--skip-existing` | не переробляти те, для чого результат уже є |
| `--no-tree`, `-v`, `-q` | коротший / докладніший / мовчазний вивід |

Постійні налаштування зручніше тримати у файлі: скопіюйте
`config.example.json` у `config.json` і виправте потрібні значення.
Ключі командного рядка мають вищий пріоритет за цей файл.

## Ручний зміст

Коли автоматика не влучає (скан, незвична верстка або просто хочеться
своїх назв), покладіть поруч із PDF файл `<ім'я>.outline.json`:

```json
[
  { "title": "Практичне заняття 1", "page": 1, "children": [
      { "title": "Основні означення", "page": 1 },
      { "title": "Приклади", "page": 3 }
  ]}
]
```

Номери сторінок — від 1, як їх бачить читач. Підтримується й плаский
запис зі стовпчиком `level`:

```json
[
  { "level": 1, "title": "Практичне заняття 1", "page": 1 },
  { "level": 2, "title": "Основні означення", "page": 1 }
]
```

## Як програма знаходить заголовки

Заголовок — це не просто «великий шрифт». Програма будує таблицю всіх
накреслень документа й перевіряє, які з них поводяться як рівні змісту:

* більший кегль, напівжирність або окрема гарнітура порівняно з основним текстом;
* таким стилем набрано небагато рядків, і вони короткі;
* рядки вирівняні однаково (по лівому полю або по центру) і стоять окремим блоком;
* над ними є додатковий відступ, часто вони починають сторінку;
* стиль займає рядок цілком, а не виділяє слово посеред речення.

Далі окремо відсіюються колонтитули, номери сторінок, підписи до рисунків,
надруковані сторінки змісту, титульні аркуші, формули (зокрема математика
KaTeX і TeX, кегль якої в PDF нічого не означає) та повтори назв слайдів.
Назва, перенесена на кілька рядків, склеюється в один пункт. Якщо стиль не
більший за основний текст, від його рядків додатково вимагається номер
розділу — інакше «Приклад 1.» посеред абзацу потрапляв би у зміст.

Коли структурних заголовків у документі майже немає (типово для слайдів),
вмикається запасний прохід по мітках на початку абзаців — «Приклад 3.»,
«Теорема (…)» — але лише якщо такі мітки одноманітні й їх небагато.

Окремо враховано випадки, на яких прості правила помиляються: сторінки з
/Rotate 90 (координати тексту там лишаються в системі неповернутого аркуша),
обрізані сторінки (CropBox), однакові за формою заголовки на кожній сторінці
(«Практичне заняття 1», «Практичне заняття 2») — їх не можна плутати з
колонтитулом.

Точність перевірено на розміченій добірці з 12 реальних документів різних
типів (конспекти з Obsidian, стаття LaTeX, слайди Beamer і PowerPoint,
звіти Word, книжки, скани): повнота 0.94, точність 0.98. Ще 45 випадкових
PDF з диска пройдено без жодного збою.

## Якщо щось пішло не так

* **«у файлі немає текстового шару (скан)»** — сторінки є зображеннями.
  Допоможе лише розпізнавання тексту (OCR) або ручний `*.outline.json`.
* **«заголовків не знайдено»** — документ справді однорідний. Спробуйте
  `run.bat --fallback pages` або опишіть зміст руками.
* **«немає доступу… файл відкритий у переглядачі»** — закрийте `*_outline.pdf`
  у програмі перегляду й запустіть ще раз.
* **«The .venv folder is broken»** — таке буває після перевстановлення Python
  або коли теку проєкту перенесли з іншого комп'ютера: видаліть теку `.venv`
  і запустіть `run.bat` ще раз, вона створиться заново.
* **`run.bat` чекає натискання клавіші, хоч ви запустили його з консолі** —
  так задумано для запуску подвійним клацанням (інакше вікно закриється
  миттєво). Щоб вимкнути паузу у скриптах, задайте `NO_PAUSE=1`.
* **У змісті зайві пункти** — підніміть суворість:
  `"detection": { "score_threshold": 4.5 }` у `config.json`.
* **Бракує пунктів** — навпаки, знизьте поріг до 3.0 або збільшіть `max_depth`.

## Склад проєкту

```
run.bat                  зміст для готових PDF
export.bat               перетворювач md -> PDF зі змістом
requirements.txt         залежності (PyMuPDF)
config.example.json      зразок постійних налаштувань
data\                    вхідні PDF і результати
md\                      вхідні .md і готові PDF
obsidian_plugin\
    pdf-outline-export\  плагін, який програма ставить у сховище Obsidian
pdf_outline_maker\
    cli.py               аргументи та головний цикл
    md_export.py         перетворювач md -> PDF (export.bat)
    md_outline.py        зміст із розмітки .md
    config.py            налаштування
    discovery.py         пошук файлів, імена результатів
    extract.py           читання тексту з типографікою
    model.py             рядок, стиль, вузол змісту
    analyze.py           таблиця стилів, основний текст, службові зони
    detect.py            вибір заголовків
    tree.py              побудова дерева
    overrides.py         ручний зміст із JSON
    writer.py            запис закладок у PDF
    pipeline.py          обробка одного файлу
    report.py            вивід у консоль
    text.py              українські форми числівників
tests\                   тести (python -m unittest discover -s tests)
legacy\                  перші чернетки скриптів, лишені для історії
```

Потрібен Python 3.10+ (перевірено на 3.12) і Windows.
Єдина зовнішня залежність — [PyMuPDF](https://pymupdf.readthedocs.io)
(ліцензія AGPL-3.0).

Для `export.bat` потрібен ще настільний Obsidian 1.5 або новіший
(перевірено на 1.13.7) з увімкненими community plugins.
